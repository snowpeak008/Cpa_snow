# Snow Console 独立多用户试用入口 · 1.0.3 / A.0.4

2026-11-04 已按授权部署为独立服务器服务，不替换现有 CPA 管理后台或配额入口。
**已上线的是多用户控制台试用；尚未接通 CPA 资源同步及调用调度。**

## 可用功能与边界

- 独立用户名/密码登录；管理员创建用户、禁用用户、分配本服务内资源和设置政策。
- 普通用户不能导入或删除账号、修改凭证或代理，只能启停分配给自己的账号、在 1～10 内调相对权重。管理员停用的账号不能自行恢复。
- 用户可以创建客户端 Key、添加 GPT/Claude/Grok 上游渠道；所有 Key 和资源只保存到本服务独立数据库，创建的 Key **不能用于现有 CPA**。
- 用户可以用当前密码、新密码和二次确认修改密码。服务端限制 8～256 字符，改密后旧会话全部失效。二次确认由页面校验。
- 当前额度、并发政策和权重没有接入实际 CPA 调用侧，不能当作已经生效；不显示虚构余额。
- 上游地址禁止本机/非公网 IP 和配置名单内的 CPA 主机。DNS 校验器尚未接入真实出站传输；上线调用侧前需完成目标 IP 固定、TLS 校验及禁止重定向。

## 访问

- 服务器仅监听 `127.0.0.1:8320`，不开放公网管理端口。
- 经授权 SSH 通道转发 `127.0.0.1:18320 -> 127.0.0.1:8320` 后，用户入口 `http://127.0.0.1:18320/user`，新试用管理员入口 `/admin`。
- 生产原 CPA 管理后台和配额入口保持原地址。原用户 SSH 包没有自动升级；其他电脑需由管理员配置受限通道允许的新转发，不能发放管理员 SSH 私钥。
- 浏览器 Host/Origin 必须与 `--public-origin` 一致，不能随意换本地端口。监听端口与转发后的浏览器端口可以不同。

## 在另一台服务器复用

Python 3.10+，仅标准库。建立专用低权限系统用户 snow-console，将运行文件放在 `/opt/snow-console-trial/releases/1.0.3`，代码 root 所有、专用组只读；数据目录 `/var/lib/snow-console-users` 由服务用户独占（0700）。

用 `python app.py --data YOUR_PRIVATE_DIRECTORY --bootstrap-admin YOUR_ADMIN_NAME` 初始化空库，提示时设置管理员密码。随后通过管理员界面创建普通用户。不包含默认管理员密码、用户密码或数据库；实际生产初始化不是本归档的一部分。

归档的 `upstream-policy.json` 是脱敏模板，已去除实际服务器地址，不与生产配置字节相同；必须替换示例域名并补齐自身全部地址/域名。按实际环境调整 systemd unit 的路径、用户和 public-origin，配置数据目录权限后启用服务。unit 限制为 96M 内存、25% CPU、仅本机网络；运行服务不读取 CPA 管理密码或生产配置。真实上线时应核对服务器版本及内存资源。

## 校验与回退

运行 `python verify.py` 校验归档文件；运行 `python -m unittest -v test_console` 执行 33 项隔离测试。归档包含实际部署文件和脱敏检查结果，不包含账号、Key、管理密码、SSH 私钥、数据库或请求日志。

停用试用服务：`systemctl disable --now snow-console-trial.service`；保留独立数据目录，不恢复或覆盖 CPA 数据。只关闭本试用 SSH 转发，不终止其他隧道。此回退不会停用或替换现有 CPA。

完整正式接入仍需实现持久化同步/回退、原账号与 Key 归属迁移、调用侧用户合计限制、真实额度受限读取及出站防回环。本发布不宣称这些工作已完成。
